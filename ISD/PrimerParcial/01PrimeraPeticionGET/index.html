2. Explicación de los Resultados

Al ejecutar el programa, sí se logró establecer la conexión exitosamente. Nuestro cliente realizó una petición asíncrona mediante el protocolo HTTP a la URL del backend alojado en Render.

El servidor recibió la petición, se conectó internamente a la base de datos para consultar la información requerida, procesó los datos y devolvió una respuesta válida al cliente sin arrojar errores.

3. Elementos Obtenidos en la Respuesta

A través del objeto Response obtenido por la función fetch, se extrajeron los siguientes elementos clave:

  • Protocolo y URL: Se verificó que la petición viajó a través de un canal seguro utilizando HTTPS sobre TCP, apuntando exactamente al endpoint solicitado.
  • Código de Estado (Status): Se obtuvo un código 200 OK. Esto indica a nivel de protocolo que la solicitud GET fue recibida, entendida y procesada con éxito por el servidor.
  • Tiempo de Ida y Vuelta (RTT): Se calculó el Round-Trip Time en milisegundos. Este valor representa el tiempo total que tomó el viaje de la solicitud desde el cliente hasta el servidor en la nube, más el tiempo que tardó en regresar la respuesta con los datos.
  • Cuerpo de la Respuesta: Se recibió un objeto en formato JSON. Tras parsear la respuesta con await respuesta.json(), se obtuvo la estructura de datos proveniente de la base de datos (los registros de los talleres), la cual fue impresa en consola debidamente formateada.
